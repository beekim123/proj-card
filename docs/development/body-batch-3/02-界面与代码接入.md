# 第3批 · 原生界面与代码合同

本页的新增字段/接口是第三批要实现的合同，不是现有代码已支持。正式id、数值和时序见01；存储版本和旧局处理见03。

## 1 公共接口与字段

新增纯模块 `rules/progression.gd`（建议class_name为RulesProgression），不读文件、时钟或随机数：

```gdscript
static func tier_multiplier(tier: Variant) -> float
static func unlocked_tier(records: Dictionary) -> int
static func can_start_tier(records: Dictionary, tier: Variant) -> Dictionary
static func apply_clear(records: Dictionary, tier: int) -> Dictionary
static func has_big_gem(records: Dictionary) -> bool
```

- 正式倍率唯一来源 `RC.DIFFICULTY_TIERS=[1.0,1.5,2.0,3.0,4.0,6.0]`。非法tier时 `tier_multiplier` 返回-1.0并设last_error；合法tier必须是0–5整数，不能接受1.5、负数或未知档。
- `can_start_tier` 返回 `{"ok":bool,"reason":String}`；只允许0到 `unlocked_tier(records)`，不改参数。
- `apply_clear` 返回新records，仅使fullWins+1、bestClearedTier取最大；不在这里重复增加played/wins/retreats。非法tier返回原值的深副本并设last_error。该函数处理一个已确认完整通关事件；去重由runId原子回执负责。
- `unlocked_tier`：fullWins=0时为0；否则为 `min(5,bestClearedTier+2)`。`has_big_gem` 为fullWins>0。不另存一份可矛盾的解锁等级或奖章布尔值。

`Run.create_run(seed: Variant, options: Dictionary={}) -> Dictionary` 保持入口，新增options：`tier`默认0、`unlockedTier`默认0、`tuningScale`默认1。应用先用真实records调用can_start_tier，再将其派生的unlockedTier传入；规则入口也检查tier不越界/不超授权上限，非法输入返回空字典、设last_error且不消耗RNG。

新局运行状态：

```text
contentVersion = "body-batch-3"
difficulty = { tier: 0..5整数, tuningScale: 有限正数 }
hpScale = DIFFICULTY_TIERS[difficulty.tier] * difficulty.tuningScale
guardUsedThisAct = bool
```

hpScale为派生值，建局/读档严格核对。正常首页新局tuningScale固定1；debug血量倍数与旧局迁移使用tuningScale，不能把旧hpScale=2误判成加码2。debug仍使用隔离存档目录。

现有debug“血量倍数”按钮（`game.gd:2148-2151`）直接改全局 `RC.RUN.hpScale`，`run.gd:29,58` 再读它。当前模式下create_run与make_monster不再读全局倍率，只用state的派生hpScale；debug按钮改为记下数值，由下一次 `start_adventure` 作为 `tuningScale` 传入。冻结LEGACY_RUN的oracle（`tests/oracle_runner.gd:102-105`）继续按原方式设全局倍率，不动。`R.debug_relic_selection`（`run.gd:541`）重建本局时须带上原difficulty，不能悄悄回到基础档。

`Profile.apply_safe_exit(profile: Dictionary, relics: Array) -> Dictionary` 新增为安全带回并集；保留 `apply_retreat` 兼容入口委托它。profile仍为v1，顺序由正式19件RELIC_IDS决定，初始6件不变。失败/放弃不调用安全带回。

records新增 `fullWins:int>=0`、`bestClearedTier:int=-1..5`；完整结构见03。旧wins保留历史含义，首页“通关”只能读fullWins。

新增纯 `Run.cleared_fights(state:Dictionary)->int` 统一纪录与结算显示：以fight-1为前沿；若stats.fights已有当前fight的won=true确认，则计fight；限制0–18。奖励/去留阶段放弃仍计入刚赢的仗，doors表示待进下一房则不计未打房，战斗中打穿但尚未结束回合也不提前计赢。冻结旧模式继续其原合同，旧记录迁移不追溯猜改。

## 2 规则与生命周期入口

| `rules/effects.gd:lifecycle` | guard取得时立即给本幕一次；新actStart只重置本幕盾，不在fightStart每仗重置。不要为重置盾重跑所有runStart，否则heart会重复增加心上限。 |
| `rules/run.gd:choose_act_exit/next_fight` | 前两幕都允许继续；第三幕不生成act_choice。跨幕保留牌组/成长/宝物/心上限，初始化第三幕战斗及盾，不能重抽已展示奖励。 |
| `rules/run.gd:settle/update_records` | 18仗胜利才授fullWins/最高通关档；带走与失败不解锁。保留所有终局二次调用拒绝与recordsApplied保障。 |

原 `combat:turnEnd` 在lifecycle列表里先执行攻击，不能仅把regrow或guard挂在其后期待自动得到正确顺序。可增加明确的beforeAttack生命周期处理regrow；guard必须在本次心损失发生前拦截。代码实现形式可按现有风格，以上可观察时序不可变。

第三幕boss配置有healFull=true；沿用fightWon回满心后直胜利，不能因当前最后一仗早return而漏过。冻结一幕旧模式仍按其原房间标记/时序回放。

`run_types.gd` 中旧怪/宝物/字段常量并不等于实际存档白名单；真正校验在Save、RC各池及Effects。阶段集合继续共用RunTypes，新增字段与内容必须在实际编码/验证入口接上，不能只改常量列表。

## 3 首页、难度与纪录

首页保留开始/继续/练习/收藏/规则/设置，新增简短“难度”选择页；不在战斗设置里切正式档位。

| 状态 | 展示/操作 |
|---|---|
| 未三幕通关 | 基础档可选；加码1–5锁定，写“通关基础档后解锁加码1、2” |
| 已解锁 | 展示基础档、加码1–5各自血量倍率；可选范围由unlocked_tier派生；选中后按钮“以此难度开局” |
| 有活动档 | “继续这局”明确当前档/幕/房间；继续不受首页当前所选新局档改变 |
| 记住的档位 | 存为 `settings.tier`（0–5整数，默认0），在“以此难度开局”时写入；`persistence.gd:_settings_of` 白名单同步加这一项，否则会被丢掉。结算页“再来一局”也按settings.tier开局，同样先过can_start_tier |
| 记住的档位后来不合法 | 回退基础档并提示；未知档位不进入create_run，不把整数强截成另一个正式档 |
| 完整纪录 | 最远已过仗数0–18、带回家retreats、三幕通关fullWins、最高一回合、最大超杀、最高已通关加码；无通关时最高档显示“尚未通关” |

“最高已通关加码”读bestClearedTier，不能显示最高解锁档/最高尝试档。解锁页可单独显示当前可选范围。旧wins可以保留为历史数据，不标成三幕通关次数。

最远文案：0还没有纪录；1–5为门厅第(cleared+1)间；6门厅已过；7–11长廊第(cleared-5)间；12长廊已过；13–17宝库第(cleared-11)间；18宝库已过。战斗进度仍只显示当前幕6格，顶栏标幕/间/当前难度。

## 4 去留、完整通关、收藏

- 第二幕去留同时有“带着宝物回家”“接着追”，仍先选中、再“就这么办”；支持1/2、Enter/Space且防重复。持有5件时长名字可读，内容滚动不挡标题/底栏。第二幕去留的标题和两段文案直接沿用第一幕（`game.gd:2404,2411-2412` 的act==1分支），不再显示“长廊已过”。
- 规则页 `game.gd:2056` 改为：“门厅、长廊、宝库各有六间。打赢前两条龙，先挑宝物，再决定去留；打赢宝库的龙就是通关。只有门厅精英增加手牌上限。”
- 第三幕龙结束直接进入完整胜利页，标题“通关”，老门环：“这回，最大的那颗也归你了。” 展示大宝石奖章、当前档、6件所持宝物及新收藏标记、完整18仗纪录。
- 首次胜利提交成功后展示“获得大宝石”和具体新解锁档；重复胜利显示“大宝石已收藏”，仍加一次fullWins，不重复新增普通收藏。
- 结果字段：与现有 `result.newCollection` 同处（`persistence.gd:253-255`）在成功提交时写 `result.firstBigGem:bool`（提交前fullWins为0）与 `result.newUnlockedTiers:Array[int]`（提交前后unlocked_tier之差，按升序，无则空）。只在rename成功后合并进调用者result。runId已结算的去重分支（`persistence.gd:245-248`）不重算这两项：缺字段时显示“大宝石已收藏”、不显示新解锁。截图旁车与UI测试读这两个字段。
- 存储未成功时显示“通关进度尚未保存”“重试保存”，不把新解锁/奖章显示为已落盘。retry/go_home/再来一局沿用原子回执，不双计。
- 失败页仍说明“这趟新宝物没有带回，已有收藏还在”；这句不能再出现在victory。带走页不称完整通关，也不展示加码已解锁。
- 收藏室为n/19，新增4件普通宝物按正式顺序；奖章独立显示。锁定项仍能看到名称/解锁说明；已收藏项完整效果可读，能滚到第19件。
