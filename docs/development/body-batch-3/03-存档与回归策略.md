# 第3批 · v6存档、进度与回归

## 1 新写入格式

活动档外壳version=6，state.contentVersion=`body-batch-3`。活动阶段仍为battle/loot/doors/shop/relic/act_choice；victory/retreat/defeat为终局，不作为普通活动档保存。第三幕没有act_choice。

在现有状态上加入 `difficulty={"tier":0..5整数,"tuningScale":有限正数}` 与 `guardUsedThisAct:bool`。hpScale须精确等于正式tier倍率×tuningScale；普通新局tuningScale=1。difficulty子对象只接受上述两个key，拒绝未知档/额外模式参数；未知大版本/内容版本保留原文，不静默当基础档。

monsters固定18项；act/room/fight关系仍 `(act-1)*6+room`。第三幕怪池/指定怪、dragon.layerRules、奖励去向都按当前正式配置校验，持有普通宝物≤6，初始池是已记录的startingRelics且只含19正式id。已展示的候选可以少于3件；排除已持有，不允许大宝石进入候选。

继续严格验证唯一牌id/nextCardId、12种额外牌各≤2、消耗标记、桌上动态解析mask、牌组守恒、心数/心上限、两组同长撤回快照、成长/RNG、stats、房间合法怪/血量/层数/倒计时、怪伤害与当前倍率的数值边界。不能为修L05放宽牌id条件。

cap状态的历史不能被全局断言m≤32误杀：跨层前的历史允许更高倍率，封条/打穿后的倍率也可更高。用对应历史怪规则和当张上下文校验，不能把当前层状态套到旧快照。regrow的turnStartHp是当回合起始值，恢复后仍在合法血量范围。

guardUsedThisAct不持有guard时为false；取得后false，消耗后true，下一幕false。run.hist中也保存此布尔值；game.hist仍只保存纯核心牌状态。彩虹回心使用已有run.hearts撤回字段；任何恢复/预览都不能提前回心或重新给盾。

彩虹回心的行字段：现有 `row_entry`（`rules/save_state.gd:53,71-73`）只允许药水行带heal且≤2，原样保留会把彩虹回心后的战斗拒存（与L05同类的静默拒存）。新增布尔 `entry.rbHeal`，只写在本回合实际新触发彩虹的那一行，并按下表校验；row_entry需要能读到所在game的relics与rainbow：

| 行 | 无rbHeal | 有rbHeal（须rb=true、game.rainbow=true、持有rbheal） |
|---|---|---|
| 药水 | spent=true，heal∈{1,2}（原规则） | spent=true，heal∈{2,3} |
| 非药水 | 不得有spent/heal（原规则） | 无spent，heal=1 |

同一row（含每个game.hist快照）至多一行带rbHeal；其他被高亮成rb=true的历史行不得带。离开row进入deck/discard时照旧由copy_card去掉这些字段；回合提交时consume_potions只按spent移除药水。冻结两幕模式不认rbHeal。须有“触发后存档→读档→撤回→重打”的往返用例。

## 2 冻结验证与无RNG迁移

先在 `run_config.gd` 明确三种模式：

| 配置 | 内容 | 写档版本/内容版本 | 可读run版本上限 | 纪录外壳 | 用途 |
|---|---|---|---|---|---|
| LEGACY_RUN / use_legacy | 原一幕6仗、9工具、10宝物 | v4 / 原规则 | 4 | 原平铺 | 原H5 oracle、312黄金、400历史 |
| BATCH_TWO_RUN / use_batch_two | 冻结e383两幕12仗、12工具、15宝物 | v5 / body-batch-2 | 5 | v2 | v5合法性判断、第二批回归 |
| 当前RUN / use_current | 三幕18仗、12工具、19宝物 | v6 / body-batch-3 | 6 | v3 | 第三批生产与新回放 |

配置里的saveVersion/contentVersion/可读上限/纪录外壳版本作为单一来源；不能继续只用 `legacy?4:5` 决定版本。`save_state.gd:226,295` 与 `persistence.gd:79,88,91,117,204` 的版本判断全部改读配置，不写死数字。冻结两幕模式的Persistence行为保持原样：只读写外壳v2、farthest≤12、v6按“未来版本”保留原文——`tests/test_batch_two_save.gd:103,129-131` 这两条旧断言因此不改。旧模式的create_run、记录、效果可观察行为保持旧合同，不随当前18仗默认值串改。临时切换验证模式的所有return路径都恢复原配置，测试验证无全局泄漏；可传验证上下文代替临时全局切换，避免无关重构。

### 合法v5→v6

1. 在冻结BATCH_TWO_RUN下先完整验证v5，包括12项monsters、15池与已有候选、relics≤5；不能先按18项校验再称旧局坏档。
2. 深拷贝原合法state，完整保留runId、当前位置、牌组/id/顺序、game.rngState、成长、心数、怪、已选门/奖励候选、startingRelics/relicPurpose、两组hist和统计。
3. 仅补未来第三幕monsters占位 `[tree,tree,armor,tree,tree,dragon]`，不抽签；contentVersion改body-batch-3，difficulty设tier0、tuningScale=原hpScale，hpScale数值不变；guardUsedThisAct及每个run.hist同名字段补false。
4. 当前第二幕龙后的act_choice仍停在原位，升级后页面允许继续第三幕；不自动领取、不自动继续、不重抽候选。已结束带走局的记录不复活成活动局。
5. 切回当前配置验证迁移产物。迁移本身不调用create_run/reset_battle_cards/next_fight/shuffle，不消耗RNG。未来新生成奖励使用第三批正式池；不能承诺整段未来旅程仍与两幕旧玩法完全相同。

### 合法v4→v6

保留原v4严格验证和既有v4→第二批状态的语义，再补上述v6字段/未来第三幕。v4没有runId时仍由持久化适配器以原文hash绑定的一次性迁移身份赋值；规则层不读时钟/系统随机。迁移写失败后重试身份不变。

### 文件迁移与回执

原文先按版本/hash备份，再写转换档；备份/身份/转换任一步失败都保留原活动档，不提前写成功标记。v5已有runId必须原样保留，不能像当前通用migrated分支那样一律生成新id。

`Persistence.load_run/save_run` 的未来版本上限取当前配置的可读上限（当前模式为6，冻结两幕仍为5）；高于上限一律保留原文件。当前模式的“未来版本”新用例改用v7。clearedRun保留原始活动档字节比较语义，不随迁移重编码旧回执；settledRunIds继续拦重复局。已结算旧档、较旧generation回调不得清掉新活动档。

## 3 纪录外壳v3与收藏

```json
{
  "version": 3,
  "records": {
    "played": 0,
    "wins": 0,
    "retreats": 0,
    "farthest": 0,
    "bestTurn": 0,
    "maxOverkill": 0,
    "fullWins": 0,
    "bestClearedTier": -1
  },
  "profile": {"version": 1, "collected": ["same", "once", "white", "rainbow", "heart", "grow"]},
  "settledRunIds": [],
  "clearedRun": null
}
```

- played：每个胜利/带走/失败/放弃的独立runId只加一次。
- wins：保留既有历史旅程胜利累计；新三幕victory也按原通用逻辑加1，不能清零旧值。它不是新三幕解锁凭据。
- fullWins：只有当前第三批18仗victory加1。旧一幕wins迁入时fullWins=0，不伪造大宝石/加码。
- bestClearedTier：没有完整三幕胜利为-1；有则为实际胜利tier的最大值0–5。fullWins=0必须对应-1，fullWins>0必须对应0–5。
- retreat仅加retreats，不加wins/fullWins/最高通关档；失败/放弃同样不解锁。完整胜利不增加retreats。
- farthest是已打赢仗的进度前沿0–18，由 `Run.cleared_fights` 统一计算：先取fight-1；stats.fights已存在当前fight的won=true确认时取fight，再限制0–18。因此战斗失败/战斗中放弃、初始宝物、等待进入下一房的doors不计未打房；当前战斗已结束的loot/shop/精英或龙奖励/act_choice中放弃则计当前fight。例：门厅龙后去留页放弃为6，第三幕精英奖励页放弃为15。完整胜利为18；不把当前已打穿但尚未结束回合的战斗提前记赢。冻结旧模式保留其原回放行为，旧纪录原值不追溯猜改。
- bestTurn/maxOverkill保持原定义；统计已打伤害，不因regrow回去而扣减，不把debug定位结果当自然平衡统计。

外壳v2迁v3：原records/profile/settledRunIds/clearedRun逐值保留，仅补fullWins=0、bestClearedTier=-1并升外壳版本。原平铺旧纪录先走现有转换（旧farthest7→6、其他f→f-1），再补新字段；不要把已是v2的已过仗值再减1。profile仍v1，15件合法旧收藏自然成为19池子集，不自动赠送4新件。

v2先按冻结旧外壳校验（farthest≤12、15件旧池、旧字段集）判断合法，再补v3字段并用新校验复核；不能直接让要求fullWins/bestClearedTier的新_is_records拒绝所有缺字段旧对象。旧平铺同样先走其版本对应校验，未知版本/损坏外壳保留原文并报告，不借迁移容忍未知普通宝物。

`_is_records/_copy_records/_read_records/_write_records` 全部同步新字段、18上限和版本（均按当前配置；冻结两幕仍是v2/12）；任一处漏改会拒读或丢字段。另加不变式 `fullWins≤wins≤played`。未来records版本高于当前配置时原文保留，读失败不能用空默认对象覆盖正式收藏。

## 4 原子完整通关

`Persistence.record_result(state,records)` 延续返回bool/last_error。一次成功提交必须同时包含：纪录、19池收藏并集、fullWins/最高通关档、runId去重回执、clearedRun。大宝石/解锁由同一份成功提交的records派生，不单写第二个文件。

顺序：克隆局/纪录/外壳→验证终局与tier→通用纪录更新→若victory且为18仗当前内容则apply_clear，若victory或retreat则apply_safe_exit→计算新增收藏/解锁/首次奖章→写同一个临时记录文件并rename→成功后替换内存与recordsApplied、最后清活动档。

IO失败时不改正式文件、不提前改调用者records/profile/result.recordsApplied，不显示“已解锁”；保留可重试局与旧存档。成功写纪录但删除活动档失败时，重启按settledRunIds/clearedRun消重，不能再领奖。

目前 `_persist` 失败后立刻 `_flush_settlements`，一次性write故障可能同次调用即重试成功；因此待保存UI测试需要持续/定次数失败适配器，不能以一次性按钮点过就宣称见过等待页。

保留相同seed不同runId分别计次、同runId重复确认只一次、迟到旧回调不能删新局的保障。加载活动档只校验difficulty本身（tier为0–5整数、hpScale与tier×tuningScale一致）；解锁资格只管新开局，已建成的合法加码局即使当前records显示的上限更低也照常可继续，不清档、不改档（对应B07“恢复与新开局权限分开”）。记录IO/版本不可读时保留活动档并报告，不能把它清成普通坏档。
