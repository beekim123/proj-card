# 本体第2批 · 规则与数值

## 1 两幕配置

每幕固定房型：小怪 → 双门 → 精英 → 双门 → 双门 → 宝石龙。`act`、`room` 从1开始；`fight=(act-1)*6+room`。`RUN.fights` 若保留，必须由 `acts[].rooms` 展平得到；不保留两套可独立修改的血量表。

| 幕 | 小怪 | 双门 | 精英 | 双门 | 双门 | 龙 |
|---|---:|---:|---:|---:|---:|---:|
| 门厅 | 20000 | 40000 | 100000 | 250000 | 450000 | 1000000 |
| 长廊 | 500000 | 700000 | 500000 | 1100000 | 1700000 | 3000000 |

门厅小怪池仍是 `chest,soldier,bear`，精英 `clock`，龙 `hug,bite,bell`。长廊小怪池依次为 `box,portrait,chest,soldier,bear`，精英 `lock`，龙 `picky,duck,six`。保留原规则：双门的怪、奖励各不相同；不再选上一只普通怪；满心时不出现回心门。

普通怪、精英倒计时3；发条兵仍是2且发条4；龙为4。新怪不自带额外韧性。保持当前1/2/3层血量显示、3颗心、7→8张手牌、12张手牌硬上限。仅第一幕精英增加1张手牌，第二幕精英不再增加。每个精英和龙后回满心；跨幕保留牌组、宝物、成长和心上限，第一回合/发条等按现有新战斗生命周期重置。

### 奖励与阶段（必须分清）

- 新开局：选开局宝物 → 第一幕第1间。
- 普通/双门战斗结束：沿用牌、工坊或回心奖励，之后进入本幕下一间。
- 精英结束：回满心、选一件不重复的宝物 → 本幕下一间。
- 第一幕龙结束：回满心、选一件不重复宝物 → `act_choice`。带走则以 `retreat` 结束并存收藏；继续则进入第二幕第1间。
- 第二幕龙结束：回满心、选一件不重复宝物 → `act_choice`。本批仅可带走，以 `retreat` 结束；不进入不存在的第三幕，不发大宝石、不解锁加码。
- 战斗失败或主动放弃：以 `defeat` 结束，本局未带出的宝物不入收藏。

用字段（例如 `relicPurpose=initial/elite/boss`）明确宝物选择后去哪里。不能继续用“持有宝物是否为空”判断所有奖励去向，也不能在选龙奖励时提前 `next_fight`。`act_choice` 是可保存的活动阶段，进入时撤回记录清空。第一幕带走与第二幕带走不算完整三幕通关；本批正常流程不产生新的 `victory`。

**终局阶段（定死）**：带走结束时 `phase="retreat"`，`result.outcome="retreat"`，`result.reason` 为 `act1` 或 `act2`。`retreat` 与 `victory`、`defeat` 同为终局阶段，不在活动存档白名单里。代码里所有“是否已结束”的判断都要改成同一个终局集合，至少包括：`abandon_run` 的已结束判断（`run.gd:348`）、`update_records` 的成绩判断、`_result` 的横幅和标题（`game.gd:1932–1965`，带走不能显示“胜利/失败/通关”）、debug的 victory 场景（`game.gd:2239`）。终局后再调用放弃、去留、出牌一律拒绝且不改状态，不得把已带走的局改判为 `defeat` 或重新结算。

**新局 `monsters` 与龙规则（定死）**：`monsters` 固定为 `RUN.fights` 展平后的12项，下标为 `fight-1`。现有实现除第1仗外，预抽的怪都会在 `start_battle` 时被覆盖，属于无效数据；本批规定：第一幕6项照现有方式预抽（随机数消耗与当前基线一致），第二幕6项不耗随机数，按固定占位填写：精英/龙房填该房 `monster`，普通/双门房填该幕 `normalMonsters[0]`，进房时照常由 `start_battle` 改写。龙的三层规矩写在怪状态里：`make_monster` 为龙增加 `layerRules`（当前幕 `dragonRules` 的副本）；`ruleFor`（`effects.gd:26`）与 `displayed_rule`（`run.gd:384`）都只读 `monster.layerRules`，不再读 `RC.MONSTERS.dragon.rules`。

## 2 新规矩

| id / 怪 | 精确定义 |
|---|---|
| `duck` / `box` 弹簧盒 | 本回合实际打出的第2、4、6…张牌，**整张最终伤害为0**，包括当张彩虹增量、锤子增量；此前伤害不变。该牌仍计张数、增长、反应、倍率、链、摸牌、回心等非伤害效果。若因此触发彩虹，本回合彩虹名额照常用掉。撤回恢复张数与彩虹标记。 |
| `picky` / `portrait` 画像 | 用动态解析后的宝石mask判断；仅1、2、4（三种单宝石）令这张的三色宝石基础伤害全部为0，之后仍照常计算反应、成长、倍率、链和额外效果。不是把所有伤害钩子最终清零；保留当前累计伤害触发彩虹/锤子的算法。 |
| `six` / `lock` 大挂锁 | 当前规矩有效且本回合已打6张时，下一张出牌命令拒绝且完全不改状态/RNG。普通牌、空托、额外牌均计张数；摸到的牌不计。第6张封条合法，封条生效后允许第7张；第7张才想用封条仍被拒绝。 |

**限六张的统一判断接口（定死）**：新增纯规则 `can_play_run_card(state) -> {"ok": bool, "reason": String}`。`play_run_card` 在拍快照、调用 `Core.play_card` 之前先调用它；不能出牌时设置 `last_error`、返回 `{}`、不改任何状态。`preview_run_card` 在不能出牌时返回 `null`；`card_warnings` 返回 `{"attack":false,"unwind":false,"blocked":true}`；`best_hint_card` 跳过这张；`preview_countdown` 返回当前倒计时。这几个函数都不能对 `{}` 读 `.v`、`.k`（当前 `run.gd:398–400`、`run.gd:418` 会在第7张时报 SCRIPT ERROR）。界面在冒险模式拿到 `null` 时不得退回 `Core.preview_card`（它不带怪，会给打不出的牌显示正数伤害，见 `game.gd:861`），而是显示“这回合打满6张了”。练习模式没有怪，不受限六张约束。

封条沿用当前“本张结算后生效”的时序；不倒改这张已经受到的缩头/挑食限制。龙跨层时，用出牌前有效规矩处理这张，伤害结算后切新层，下一张使用新规矩。规矩提示、预览、排牌试算和实际打出共用规则代码。

龙必须按当前幕取三层规则（存于 `monster.layerRules`，见第1节），不再硬读 `RC.MONSTERS.dragon.rules` 的第一幕数组。保持 `hp > 2/3` 为第一层、`hp > 1/3` 为第二层，否则第三层的边界。龙已打穿后规矩全部失效；超杀阶段仍可继续出牌。

## 3 新牌

沿用现有9种的顺序，末尾依次追加 `palette,potion,diamond`。每种额外牌最多2张；药水消耗后释放相应名额。

| id | 宝石 / 效果 |
|---|---|
| `palette` 调色盘 | 有前张时复制前张解析后的mask，强制算顺色，并给顺色链补上一个尚缺的颜色；缺色按 `[1,3,2,6,4,5]`（红黄绿青蓝品红）依次选，六色已齐则不补。把本张实际颜色加入链后再补缺色，再判断彩虹。第一张没有前张时为空托、普通反应，不强制顺色、不补色。它不消耗“断一次不算”的次数。 |
| `potion` 药水 | 红宝石牌，正常算伤害与成长，并回1颗心，最多到心上限；满心也允许打出并消耗。是本回合第一张额外牌且有“头一张打两次”时回2颗心，仍只消耗1张药水。不能借它突破上限。 |
| `diamond` 钻石 | 白宝石牌；本张每颗宝石底数×2，不改变成长次数。原石无其他效果时底数600；红加倍＋钻石时红400、绿200、蓝200，合计800。红被抱住仍为0。 |

**桌上宝石位可变的牌**：镜子、影子、调色盘在桌上记录的是解析后的宝石位，可以和配置里的 `v` 不同。定义一份共用列表 `RESOLVED_MASK_TOOLS = ["mirror","shadow","palette"]`，存档校验（`save_state.gd:54`、`save_state.gd:94` 现在只放行镜子、影子）、手牌显示预测牌面（`game.gd:891`）、彩虹提示（`run.gd:431`）都用这份列表，不再各写一份。反例：先出红宝石(1)再出调色盘，桌上为 `{type:"palette", v:1}`；按现有校验会被判为非法，这一回合每次写档都失败。

调色盘、钻石都不是重复执行类效果；“头一张打两次”不让调色盘补两色、不让钻石再翻一倍。它们依然占用“本回合第一张额外牌”的位置，之后的口袋/药水不会再被翻倍。药水后的影子只复制已定义的mask/反应，不复制回血和消耗能力；沿用影子的当前定义。

### 药水与撤回/存档

药水在桌面上仍是一张已出牌，计入张数与前张关系；本回合撤回必须还原心数、牌组、所有容器、第一张额外牌标记、RNG和统计。确认结束回合/进入下一仗后，药水不能进入弃牌堆、洗牌或工坊。

推荐实现：回合内记录药水 `spent` 标记，药水保留在 `row`，回合提交时从永久牌组和行中消费；跨回合前保持原“永久牌组=牌堆+手牌+桌面+弃牌”守恒。本回合存档需保存标记并支持恢复后的撤回；单个药水多次撤回重打只消费一次。不得用“从row提前删掉”省掉快照和消耗处理。

当前 `undo_run` 只保存怪和统计，不保存心数/永久牌组；这是本批明确要扩展的位置。练习模式没有心数，药水只展示“本牌回血仅冒险有效”，仍有正常红宝石结算；练习回合内可撤回，结束回合同样消费，不虚构冒险心数。

药水可能使牌组降到20张以下，允许这种消耗；工坊最少20张的限制只限制主动扔牌，不能让用了药水的合法存档失效。工坊抄牌仍可用，扔牌按钮在≤20张时禁用。

## 4 新宝物

| 正式id | 名称与效果 | 参考模拟器id |
|---|---|---|
| `red` | 红宝石底数×2 | `x2_0` |
| `green` | 绿宝石底数×2 | `x2_1` |
| `blue` | 蓝宝石底数×2 | `x2_2` |
| `shun` | 顺色当张伤害系数×3，原来×2；不改变下一张倍率增长 | `shun3` |
| `same4` | 同色当张伤害系数×4，原来×2；与“同色也翻倍”独立，后者仍控制下一张倍率 | `same4` |

追加顺序为上述顺序，原有10个key保持。颜色加倍不改成长阈值或次数；钻石可与相应颜色加倍相乘。顺色×3不改凑白伤害、彩虹倍数或倍率翻倍公式。同色×4单独持有时，同色后倍率仍按原来的+1；同时有“同色也翻倍”才改为×2。

## 5 收藏与本批终点

初始收藏按固定顺序为 `same,once,white,rainbow,heart,grow`。本批收藏上限15件，重复带回不增加条目。开局仅从收藏中抽取；局中精英/龙奖励从本批全15件中排除已持有的，再按原有固定种子洗牌抽至多3件。不使用系统全局随机数。

安全带走时，将 `run.relics` 与既有收藏做并集；失败/放弃不加入任何本局新宝物，也不扣掉已收藏的。收藏只解锁开局选择，不把效果永久叠加到下一局。收藏按正式宝物列表排序显示和抽签，不能依赖带回顺序或字典迭代顺序。

本批最多持有5件宝物：开局1＋两精英2＋两条龙2。第一幕龙后是唯一可继续深入的节点；第二幕的带走是当前内容边界，不伪称18仗完整通关。后续第3批在同一节点增加进入第三幕，不预先实现其效果。
