# 本体第2批 · 原生界面与代码接入

## 1 流程与文案

保持现有“先选中，再按按钮”的交互。排牌、逐张打出、超杀、跳过动画、失焦取消拖牌和键盘焦点沿用现有实现。

| 位置 | 新行为 |
|---|---|
| 首页 | 增加“收藏室”入口，显示已收藏数量；设置、规则、纪录和继续入口保留 |
| 开局选宝物 | 标题“这次带哪件宝物”，只显示收藏池里抽出的3件；不把当前15件全开放给新玩家 |
| 幕末选宝物 | 先完成宝物选择，再进入去留选择；领取前关游戏，重开仍在原选择且选项不变 |
| 第一幕去留 | 老门环一句话、当前携带宝物和提示“带出大门才算你的”；两个选项“带着宝物回家”“接着追”，选中后按“就这么办” |
| 第二幕去留 | “长廊已过，带着宝物回家吧。”仅提供带走；不用“第2批/开发中/测试版”等实现说明填充游戏界面 |
| 带走结算 | 标题“带着宝物回家”，列带回宝物、新收藏标记、最远幕/房间与原有伤害成绩；不显示完整通关或解锁加码 |
| 失败/放弃 | 说明这趟新宝物没有带回；保留已有收藏和旧纪录；按钮能回首页和重新开始。所有活动阶段（含龙奖励、去留）都保留“放弃这局”，沿用现有入口和二次确认（用户已定，见00 §7） |
| 进度条 | 只显示当前幕的6格（小怪、门、精英、门、门、龙），旁边用现有幕名标签标出“门厅/长廊”；不画12格（`game.gd:467` 现按6格间距和下标5判定龙，直接遍历12仗会越界） |
| 首页纪录 | “最远”按03 §3的已过仗数显示：0为“还没有纪录”，1–5为“门厅第 n+1 间”，6为“门厅已过”，7–11为“长廊第 n-5 间”，12为“长廊已过”。第一句写成“最远：… · 带回家 n 次”，替换原来的“通关 n 次”；第二句“最高一回合/最大超杀”不变。旧 `wins` 只保留在文件里，不显示 |
| 收藏室 | 按固定顺序显示15件，已收藏显示图标/效果，未收藏用当前占位轮廓及“带回这件宝物后解锁”；显示已收藏 n/15，支持滚动与返回 |
| 第二幕战斗/挑门 | 名称、规矩、血量、层数、预计伤害和不能打第7张的提示正确；小怪池、门奖励按01，不硬编码第一幕怪 |

老门环本批用以下短句，不增加对话选择或过场系统：

- 首次开局：“宝物带出大门才算你的。倒在里面，身上的全归龙。”
- 第一幕龙后：“现在走，这些就是你的。接着追，里头还有。”
- 进入长廊：“锁还没开，先看看你手里的牌。”
- 第二幕龙后：“这一趟够沉了，带着宝物回家吧。”
- 带走：“门给你留着，下回再来。”
- 失败：“这回龙替你保管。人回来了，就还能再来。”

首页首次开局说明可用可关闭的原生小面板；其他短句跟阶段显示，不阻止继续操作、不反复弹窗。声音先复用已有按钮/战斗/结算音，不生成新音频。

## 2 素材先占位

本轮不接入或改动 `design/新卡牌/美术` 的返稿。**当前 `ArtStore.create` 对未知id会报错并返回null，没有新key自动回退。** Dot须先补显式占位映射/适配器，用已有纹理和原生文字、图形显示新内容；覆盖 `create`、`assets[id].definition`、`set_slot_icon` 等实际访问，不能只在一处拦null。以下key与既有美术清单保持一致：

| 规则/内容key | 素材key |
|---|---|
| `box,portrait,lock` | `mon_box,mon_portrait,mon_lock` |
| `duck,picky,six` | `rule_duck,rule_picky,rule_six` |
| `palette,potion,diamond` | `card_art_palette,card_art_potion,card_art_diamond` |
| `red,green,blue,shun,same4` | `relic_red,relic_green,relic_blue,relic_shun,relic_same4` |
| 长廊 | `bg_tile_hall,prop_frame,prop_curtain` |

规矩触发的可选动画映射：缩头 `duck`；挑食 `refuse`；大挂锁每张有效计数 `click`，达到6张 `shut`。缺事件时用当前程序提示，不崩溃、不改原SVG、不阻塞规则。龙用现有素材并改变规矩牌，保留当前换层表现。

新增占位元数据放原生目录，不改冻结H5的清单/占位生成器。建议复用现有相同尺寸怪/牌/图标纹理并叠清楚的内容名称，别新增真实美术需求。占位不伪造新SVG的指纹，也不让现有素材指纹门禁失效。素材检查器继续可用；本批新增占位不能被统计成正式交稿。

## 3 结构建议

沿用现有纯规则＋应用存储＋原生界面的边界。可增加 `rules/profile.gd` 处理收藏/结算纯数据、`scripts/ui/collection_panel.gd` 组织收藏面板；只抽本批需要的代码，避免重写2300行主界面。

`_render` 增加 `act_choice` 分派，`_take_relic` 根据奖励去向更新界面；`start_adventure` 从存储拿收藏池传给规则；`_persist` 在去留阶段也写档；`_settle_records` 与 `_flush_settlements` 将收藏并入同一次结算，不另开一条无回执的保存路径。

新增纯规则接口建议：

```gdscript
static func create_run(seed: Variant, options: Dictionary = {}) -> Dictionary
# options: startingRelics:Array[String]，runId:String；由应用注入。
static func choose_act_exit(state: Dictionary, choice: String) -> Dictionary
# choice仅为retreat或continue；非法选择last_error，状态完全不变。
static func debug_jump_act_room(state: Dictionary, act: int, room: int) -> void
# 按当前debug习惯建立合法目标状态；不授予收藏、不伪造正式成绩。
static func can_play_run_card(state: Dictionary) -> Dictionary
# {"ok":bool,"reason":String}；限六张等命令级限制只在这里判断，见01 §2。
```

原有单参数纯规则测试调用可继续使用明确的默认收藏；正常应用开局必须传入已校验收藏和新的runId。runId由应用生成独立随机标识，不用规则RNG、时钟或seed代替身份；测试显式给固定runId。存储拒绝把无身份状态当成可重复领取的正式结算。

纯收藏模块建议接口：

```gdscript
static func create_profile() -> Dictionary
static func starting_relics(profile: Dictionary) -> Array
static func apply_retreat(profile: Dictionary, relics: Array) -> Dictionary
# 返回新profile，不写磁盘；去重、过滤合法id、保留旧收藏。
```

这几个新接口在当前基线尚不存在，是本批待实现合同。界面不得自行计算治疗、牌消耗、怪规矩、收藏资格或通关资格。

## 4 横竖屏与操作验收

保持当前横屏1920×1080；竖屏1080×2160逻辑布局在1080×1920窗口等比显示的已确认口径。不借本批改成另一套竖屏。

去留、收藏、幕末宝物和带走结算均要支持鼠标、触屏事件、键盘焦点；小窗口内容可滚动，主按钮不被底栏盖住。按下后阶段立刻上锁，连点不重复发放或跳两间。屏幕变化、回首页、重开局要清理旧动画和回调，不能让旧结算清掉新局存档。

debug增加：跳到指定幕/间；指定第一幕去留；给新牌/新宝物；查看并重置测试收藏；触发存储失败。测试收藏只写独立目录，不污染用户正常档。调试入口不把第三幕/加码伪装成已开放。
