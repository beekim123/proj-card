# 美术源文件（art-source）

这个游戏的美术存档和参考，从设计目录的画风库（`design/style-lab/`）同步过来，2026-11-10。

- **游戏实际用的是 `public/art/`**（63 个 SVG + `public/art-manifest.json`）。这里不参与打包。
- 以后每批美术交回，都在 `returned/` 加一份，并在本文件的表里加一行。

## 美术是怎么做的

- 外包画手（AI）用代码画 SVG，每个素材一个文件。动画写在 SVG 自己的 CSS 里：
  - 代码设 `data-anim="hit"` 这类事件，播一次；
  - 没有事件时播待机。
- **SVG 是源文件。** 做进正式引擎（以后用 Godot）时，把每个动作逐帧导出成 **PNG 精灵图**。H5 里现在直接用 SVG。
- 每个素材的 id、尺寸、事件、部件、落地点、打击点都写在素材清单里：
  - 第一版是 `public/art-manifest.json`；
  - 第二版是 `v2/素材清单-v3.json`。
- 画风是"哥特"（参考第五人格那一类的气质）：
  - 焦茶近黑的手绘钢笔线；
  - 低饱和配色；
  - **只有宝石是鲜艳、发光的**（红圆、绿方、蓝三角）；
  - 不要琥珀暖光、不要火光；
  - 怪是"古堡里活过来的旧东西"，诡萌，不吓人。
  
  细则在 `style-gothic/README.md` 和 `style-gothic/style.config.mjs`。

## 文件夹

| 文件夹 | 是什么 |
|---|---|
| `style-gothic/` | 哥特画风：规则（`README.md`）、配色（`style.config.mjs`）、定画风时的 5 个试画角色（`out/`，SVG + PNG） |
| `returned/v0-demo/` | 木桩试玩的基础素材 37 个：宝石、牌框、木桩、桌布、界面、特效。SVG + PNG + 交付说明 |
| `returned/v1-b1/` | 第一版第 1 批样稿 5 个：宝箱怪、锤子、两颗红宝石、心 |
| `returned/v1-b2/` | 第一版第 2 批 24 个：4 只怪、4 张额外牌原画、额外牌牌框、7 颗宝石、界面件、特效，加宝箱怪和锤子返修 |
| `returned/v1-b3/` | 第一版第 3 批 11 个：牌背、进度节点、横幅、战利品宝箱、徽记、断石柱、特效 |
| `review-pages/` | 第一版三批的验收页，单个 HTML 文件，素材都内嵌在里面，浏览器直接打开就能看：桌面场景、逐帧条、出框检查、新旧对比。还有第 2 批的返修小意见 |
| `v2/` | 第二版：素材清单第 3 版（75 个，字段 `v2` 标了哪一批要画）、第 1 批美术需求（发出去的那份） |

每个 `returned/*/` 里：
- `practice.json`：这一批是什么、什么时候交、验收结论。
- `art/svg/`：交回的 SVG 原样。
- `art/png/`：2 倍预览图。
- `art/manifest.json`：那一批的清单。

## 已知问题（第二版要改的）

- **动起来"卡"**：评估逐格量过，不是掉帧。原因有两个：
  - 待机里每个部件各自用 `steps()` 分格、互不同步，加上线条沸腾，看起来像在抖；
  - 受击、出手幅度小、节奏匀，没有"一下到位再弹回"。
- 第二版的新动法写在 `v2/第1批-美术需求.md` 第 2 节：同一个动作所有部件同一组时间点换姿势，用"停住"代替逐格，待机顺滑呼吸。先拿宝箱怪做样稿，过了再改另外四只怪。
- 口袋、磨石的原画看不出效果，第二版重画。
